# pyCVQRScanner v2

## 人肉手写内容

工作中需要将大批量的扫描单据上的二维码识别出来，单据为联单打印纸，打印质量与激光或喷墨无法相比，且单据较小，内容元素较多，导致二维码所占面积比较小。生成单据的系统又比较老，二维码生成的容错率比较低。起初尝试epson配套的DCP软件，发现又大量的破损二维码无法识别、多联单收回蓝联或黄联无法识别等问题。多次尝试调整DCP的扫描配置，但是始终无法得到令现场同事满意的识别率。现场条件限制也无法使用云服务来进行便捷的二维码识别能力。

面对单据破损二维码缺失的情况，按照二维码的容错纠错能力，定位角缺失的码是无法识别的。但偶然发现手机微信的扫码能在较短时间内就识别出，就搜索了一下，发现腾讯将扫码识别的工程成果提交给了opencv，顿时发现一线希望，通过opencv-contrib wechatQR包进行了初步尝试，对二维码的识别效率和识别率都是碾压级别的，但是怎么也无法识别破损的二维码？然后查找了文档，发现开源的只是核心二维码识别功能。对各类工程情况，是需要辅助编写各类预处理的。增加了多种预处理后识别率确实大幅提升至80%左右，但是对定位角破损的二维码图片还是无能为力。

面对这种情况，尝试交给AI自行解决，也没有获得很好的效果。后来偶然间了解到CTF竞赛中Misc分类中的二维码题目，这类题目大多是提供缺损的二维码要求进行推理并获取到二维码中真正的数据。看了很多参赛选手对二维码题目的思路后产生一个思路，尝试借鉴CTF竞赛的解题思路在代码层面进行几何重构补全，最终在几何补全的基础上实现了对定位角缺失图片的识别。

最后再用AI对整个处理进行了大幅度的优化和改写，形成现在的这个工具。

虽然是又造了个轮子，但确实没有发现过能高效在本地进行二维码多复杂度识别的工具。网上一些网页工具写着能修复破损但当我将缺定位角的图像上传根本连FP都识别不到。而能找到得一些能识别的软件都只提供成品软件来使用，无法集成。就此将这个工具开源，希望能帮上有需要的人的忙。

**以下开始全部为AI生成**


基于 OpenCV WeChatQRCode 的高难度二维码批量识别与文件分发工具。

专为**被裁切、低对比度、红章遮挡**等普通扫描器无法识别的单据标签设计，识别率在测试集（30 张）上达到 **100%**。

## 环境要求

- Python >= 3.12
- [uv](https://docs.astral.sh/uv/) 包管理器

## 快速开始

```bash
# 1. 同步依赖（首次运行或依赖变更后执行）
uv sync

# 2. 扫描指定文件夹
uv run main.py <输入文件夹路径>
```

**示例：**

```bash
uv run main.py ./my_labels/
uv run main.py C:/scans/batch01/
```

## 功能说明

程序扫描指定文件夹内的所有图片（`.jpg` / `.jpeg` / `.png` / `.bmp` / `.tiff`），对每张图片执行二维码识别：

| 识别结果 | 处理动作 |
|----------|----------|
| **成功** | 以二维码内容作为文件名重命名，移入项目根目录的 `output/` |
| **失败** | 保留原文件名，移入项目根目录的 `failed/` |

> 每张图片有且仅有一个二维码。

**文件名规则：**
- 二维码内容中的 Windows 非法字符（`< > : " / \ | ? *` 及控制字符）自动替换为 `_`
- 首尾空格和点号自动去除
- 文件名超过 200 字符时自动截断
- 同名文件自动追加序号（`_2`, `_3` ...）避免覆盖

## 识别流水线

程序采用 4 层短路求值策略，任一层识别成功立即返回：

| 层级 | 策略 | 典型耗时 | 说明 |
|------|------|----------|------|
| Layer 0 | 原图直接识别 | ~50ms | 适用于清晰、标准的高对比度二维码 |
| Layer 1 | ROI 裁剪 + 增强 + 多尺度 | 0.3~14s | 核心命中区，针对右上角单据优化的多种 Gamma/CLAHE 组合 |
| Layer 2 | 全图增强 (CLAHE + 锐化) | 2~5s | 处理全图偏暗或模糊但未被裁切的场景 |
| Layer 3 | CTF 风格定位角修复 | 1~5s | **高阶修复**：针对缺失 1 个定位角的二维码，通过几何推算重绘模板 |

**超时保护：** 单张图片处理超过 20 秒自动放弃，移入 `failed/`。

## 🛠 开发规范 (Development Standards)

项目遵循严密的工程规范，确保代码的可读性与稳健性：

- **显式引用 (Explicit Imports)**：禁止使用 `import xx` 裸导入。所有依赖必须通过 `from xx import yy` 形式明确引入。
- **防止命名冲突**：对于 `cv2` 中易与 Python 原生或 `numpy` 冲突的函数（如 `merge`, `split`, `resize`），统一使用别名（如 `cv_merge`, `cv_split`）。
- **WeChatQRCode 单例模式**：WeChatQRCode 模型加载成本较高（~1s），系统在 `pipeline.py` 和 `qr_repair.py` 间共享 detector 实例，全局仅初始化一次。
- **路径自适应**：所有路径引用均基于 `Path(__file__)` 自动推导，确保在项目根目录或子目录调用时均能正确加载模型。

## 日志

运行日志写入 `logs/scan_YYYY-MM-DD.log`，保留 7 天，单文件上限 10 MB。

## Benchmark 验收

使用内置 benchmark 脚本可对任意 scanner 模块进行量化评估：

```bash
# 使用优化后的 pipeline 进行全量验收（目标：识别率 >= 90%）
uv run benchmark.py --scanner src.pipeline

# 查看报告
# reports/benchmark.md
```

`benchmark.py` 支持通过 `--scanner` 参数加载任意符合以下接口的模块：

```python
def scan(image_path: str) -> list[str]: ...
```

## 📂 项目结构

```
pyCVQRScanner-ver2/
├── main.py              # 业务入口：处理文件夹遍历、文件名清洗与物理分发
├── benchmark.py         # 性能评估工具：量化识别率与耗时，生成 MD 报告
├── src/                 # 核心源码目录
│   ├── pipeline.py      # 【核心调度】多层级流水线、超时熔断与单例管理
│   ├── preprocess.py    # 【增强算子】图像 Gamma 校正、CLAHE、锐化等底层实现
│   ├── qr_repair.py     # 【高阶修复】Layer 3 逻辑，集成几何修复与局部识别
│   ├── finder_repair.py # 【几何推算】定位角轮廓检测与缺失坐标数学推算
│   └── __init__.py      # 包初始化
├── models/              # WeChatQRCode 权重文件目录
├── failed/              # 自动生成的识别失败文件夹
├── output/              # 自动生成的识别成功文件夹（以二维码内容命名）
├── logs/                # 结构化日志目录
└── pyproject.toml       # 基于 uv 的项目配置与依赖管理
```
